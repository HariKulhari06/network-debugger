# Contributing to Tracea

First off, thank you for considering contributing to Tracea! It's people like you who make it a great tool for the Android community.

## 📜 Code of Conduct
By participating in this project, you agree to abide by our Code of Conduct.

## 🛠 How Can I Contribute?

### Reporting Bugs
- Check the [issue tracker](https://github.com/HariKulhari06/tracea/issues) to see if the bug has already been reported.
- If not, open a new issue. Clearly describe the problem, provide steps to reproduce, and include environment details (Android version, Device, Library version).

### Suggesting Enhancements
- Open an issue with the tag `enhancement`.
- Explain why this feature would be useful and how it should work.

### Pull Requests
1. **Fork** the repository.
2. **Create a branch** for your feature or fix (`git checkout -b feature/amazing-feature`).
3. **Write code** following the project's style (minimalist, clean, documented).
4. **Add tests** for any new functionality.
5. **Ensure CI passes** locally by running `./gradlew build`.
6. **Submit a Pull Request** against the `main` branch.

## 🏗 Development Rules

- **Code Style**: We follow standard Kotlin coding conventions.
- **Commits**: Use descriptive commit messages (e.g., `feat: add HAR export support`).
- **Testing**: Every PR should ideally include unit tests for core logic.
- **Documentation**: Update the `README.md` or internal docs if you change public APIs.

## ❓ Questions?
Feel free to open a discussion or an issue for any questions you might have!
